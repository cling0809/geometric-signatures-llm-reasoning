## Frozen-rule fidelity note

The submitted GeoVote formula is sign-dependent: candidates are weighted by
`1/(mu + eps)` when the frozen sign is `min` and proportionally to `mu` when
it is `max`.  Table 4's frozen row (accuracy 0.90, 0 repairs / 2 breaks versus
majority on held-out IDs 50--99) was generated by inverse weighting of
`geo_value` (MeanStepNorm at layer 20).  That row matches
`experiments/2026-05-20_geovote-independence/gsm8k_2048_n8/question_level_N8.csv`
restricted to IDs 50--99.  The same folder's full-set `geovote` accuracy is
0.87, which equals the sweep cell `mean_step_norm,20,min` and not the `max`
cell (0.91); unanimous `candidate_level` rows have `max_geo_conf = -min_geo_value`,
i.e. the independence-analysis `sign=min` encoding.  The paired CSV SHA is
unchanged.  The manifest `frozen_score.sign` field is therefore recorded as
`min`, and `src/geoprobe/revision/geovote.py` defaults to inverse weights so
that a re-run reproduces the locked row.

## Explicit length-matched null extension

The exact source artifact was re-read locally with PyArrow 25.0.0 and its hash
matched the manifest above.  We then ran the frozen length-matched null audit
with calibration IDs `0:50`, evaluation IDs `50:100`, seed `20260806`, and 1,000
permutations.

The null sorts candidates within each problem by `(n_gen_tokens, sample_idx)`
and permutes residualized geometry scores only within adjacent length pairs. It
uses no correctness labels and preserves each problem's candidate pool and
score multiset.  The null distribution has mean accuracy `0.88952` and mean
paired delta `-5.048` pp versus majority; every permutation is negative, with
deltas from `-8` to `-2` pp.  This is a control-null distribution, not a new
selector or an additional held-out benchmark claim.
